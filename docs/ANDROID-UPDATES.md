# Обновление Android через GitHub

Источник: https://github.com/kazievnadir-max/blackeagle-release.
Первый клиент с обновлением: **0.5.3**, `versionCode=13`, Android 11+, ARM64.
Работа ведется в отдельном Android-репозитории. Другие клиенты пока не подключены.

## Поведение приложения

- Автоматическая проверка при открытии экрана, не чаще раза за 12 часов в процессе
  приложения; после перезапуска проверка выполняется снова. Ручная проверка — в настройках.
- На главном экране появляется ссылка на новую версию. Скачивание начинается
  только по нажатию «Скачать и установить» в настройках.
- Показываются версия, размер, описание, процент загрузки. Загрузку можно отменить
  и повторить. Докачка с предыдущей позиции пока не поддерживается.
- APK проверяется и передается установщику Android. При необходимости пользователь
  разрешает установку из Black Eagle VPN, возвращается и нажимает «Установить».
- Android самостоятельно запрашивает подтверждение установки. Отказ не удаляет
  текущую версию, профиль или VPN-настройки. Установка может прервать VPN-соединение.
- После ручной проверки без обновлений показывается краткое системное уведомление
  «Установлена актуальная версия программы» (около 4 секунд). Автоматическая
  проверка без обновлений не показывает уведомлений. Текст процесса проверки
  в настройках не отображается.
- Отсутствующий канал (404) означает ошибку проверки, а не актуальную версию. Сетевая ошибка,
  неправильная подпись или формат показываются как ошибка проверки; VPN продолжает работать.

Обновление поверх установленного APK возможно при совпадающей подписи. Старые
сборки с SDK/debug-подписью несовместимы с постоянной подписью выпусков.
Первая установка 0.5.3 выполняется вручную: версии 0.5.2 и ниже еще не умеют
проверять этот репозиторий.

## Формат общего репозитория

```text
channels/
  android-arm64.json
  android-x64.json         # Только после выпуска и проверки соответствующего APK
GitHub Releases:
  android-v0.5.3/
    BlackEagleVPN-0.5.3-arm64.apk
    SHA256SUMS.txt
```

Android получает фиксированный адрес
`https://raw.githubusercontent.com/kazievnadir-max/blackeagle-release/main/channels/android-arm64.json`.
Архитектура выбирается по текущему процессу; общий `/releases/latest` не используется.
Linux, Windows и macOS впоследствии получат собственные каналы и теги.
Приватный GitHub-токен приложению не нужен.

Канал — JSON с полями `payload` и `signature` в Base64. Подпись **RSA-PSS/SHA-256**,
соль 32 байта; подписываются точные байты UTF-8 payload до Base64-кодирования.
Payload содержит `schema=1`, `platform=android`, `architecture`, `packageId`,
`versionCode`, `version`, `url`, `size`, `sha256`, `notes`.
Открытый ключ встроен в APK из `Updates/update-public.pem`.

Приложение принимает только новую `versionCode`, свою платформу, пакет и архитектуру,
HTTPS-ссылку на APK из Releases указанного репозитория, размер до 300 МиБ.
Перенаправления разрешены только на GitHub Releases и `release-assets.githubusercontent.com`.
Перед установкой проверяются точный размер, SHA-256, пакет, обе версии и текущие
сертификаты подписи установленного и скачанного APK. Смена сертификата этим
протоколом не поддерживается. Финальную проверку APK выполняет системный установщик.
Файл предоставляется ему через закрытый FileProvider только из каталога `cache/updates`.

## Подготовка выпуска

1. Увеличить `ApplicationVersion` и `ApplicationDisplayVersion` в Android csproj.
2. Собрать APK и подписать **постоянным Android-ключом**, затем проверить сборку
   на устройстве. SDK автоматически создает `Signed.apk` с отладочной подписью;
   его нельзя принимать за производственный выпуск.
3. Подготовить UTF-8-файл с описанием изменений и выполнить:

```bash
export JAVA_HOME=/path/to/jdk-17
python3 tools/prepare-android-update.py \
  --apk /path/to/BlackEagleVPN-0.5.3-arm64.apk \
  --key /path/outside/repository/update-manifest.pem \
  --build-tools /path/to/android-sdk/build-tools/36.0.0 \
  --notes /path/to/release-notes.txt \
  --output /path/to/prepared-release
```

Скрипт проверяет реальную подпись APK (`apksigner`), берет версии и ABI из самого
APK (`aapt`), считает SHA-256 и подписывает описание. Он проверяет, что ключ
соответствует открытому ключу клиента. Скрипт не публикует файлы и не печатает секреты.

4. Опубликовать GitHub Release `android-v0.5.3` с точным именем APK из вывода
   скрипта и `SHA256SUMS.txt`. Убедиться, что файл доступен без авторизации.
5. **После APK** разместить подготовленный `android-arm64.json` в `channels/`
   ветки `main` общего репозитория. Это включает предложение обновления.
   Не заменять APK под существующим именем — для исправлений выпускать новую версию.
6. Проверить на устройстве полный путь: старая версия → предложение → загрузка →
   установка → новая версия с сохраненным профилем. Проверить отмену установки,
   отсутствие разрешения и повтор после обрыва сети.

## Ключи

Постоянный ключ APK и приватный ключ манифеста — разные секреты. В текущем рабочем
окружении они находятся в `/home/nadir/.local/share/blackeagle-signing/`:
`android-release.jks` и `update-manifest.pem`. Каталог закрыт правами `0700`,
приватный PEM имеет права `0600`. Сохраните резервную копию вне компьютера.
Приватные ключи, пароли и их содержимое нельзя помещать в репозитории или Releases.
Не генерировать новый ключ манифеста при очередном выпуске: установленный клиент
доверяет встроенному открытому ключу.

Механизм предназначен для прямого распространения APK. Перед отдельным выпуском
через Google Play или F-Droid нужно выбрать их способ обновления и отдельную
конфигурацию сборки, включая разрешение REQUEST_INSTALL_PACKAGES.

## Проверки разработки

```bash
dotnet test clients/android/tests/BlackEagle.Android.Tests -c Release
```

Тесты проверяют подпись и подмену описания, несовместимую платформу, откат версии,
размер и хеш APK, перенаправления, отмену и повтор загрузки. Они не заменяют
проверку системного установщика на Android.
